## §1 — What the mechanism is (design §S4.2, re-verified at current line numbers)

Line numbers below are as read on 2026-11-19 ~14:15 IST; they have drifted

### (a) Key roles — the account concept

- `internal/provider/keys.go:30-35` — `KeyRolePreferred = "preferred"`,
  `KeyRoleReserve = "reserve"`. A legacy single key synthesises to preferred.
- `internal/provider/keys.go:99` (`EffectiveRole()`), `:108` (`IsReserve()`).
- `internal/provider/keys.go:185` (`PreferredKeys()`), `:197` (`ReserveKeys()`).
- Roles are operator-settable via the API (`docs/API_REFERENCE.md:1407`,
  "Changes one provider key's role (preferred/reserve)").

### (b) Chain construction — the reserve flag is carried on the attempt

- `cmd/codvian-router/main.go:2177-2195` — `attemptsForProvider` expands one
  provider into one attempt per registered key, marking
  `Reserve: k.Role == provider.KeyRoleReserve` (`:2195`); keys with no
  client are skipped.

### (c) Reserve-last ordering — flat path

- `internal/router/router.go:2117-2170` — `applyTailPartitions` is the FINAL
  ordering step, after scoring, adaptive partition and soft-demotion: a
  stable partition, preferred first, reserve last, never a drop (an
  all-reserve pool still serves). It runs even under an explicit contract
  order (the contract names providers, never keys). Reserve attempts are
  never hedge targets (`hedgeSecondAvailable`, `router.go:2667-2681` per
  the design; not re-read line-exact in this slice).

### (d) Reserve-last ordering — auto-combo path (the row-425 mechanism itself)

- `internal/router/account_fallback.go:163-180` — `orderPreferredReserve`
  (comment `:163`, func `:169-179`), a pure function: stable partition,
  preferred first, reserve last.
- `internal/router/autodispatch.go:330-336` — `chainForDispatch` applies it
  on BOTH paths: the multi-model path (`:332`,
  `orderPreferredReserve(e.chainForModels(ordered))`) and the single-model
  path (`:334`, `orderPreferredReserve(e.chainFor(model))`). The function's
  own comment names PARITY row 425. It is idempotent with the later
  `orderAttempts` partition (`router.go:2272` re-applies `applyTailPartitions`).
- `chainForDispatch` is on the live request path:
  `internal/router/router.go:6092` (and `:6142`, `:6165`, `:6186`, `:6205`).

### (e) Response-start failover — the opt-in half (already FULL in Area 2)

- `internal/router/preferred.go` (whole file) — opt-in, first streaming
  attempt only, rotates to ONE immediate sibling (same provider, different
  key), disarmed by the first byte, pre-commit only, breaker-neutral.
  Default `PreferredFailoverAfterDefault = 20 s` (`preferred.go:38`).
- Arming site: `internal/router/router.go:5403-5406`.
- Config surface EXISTS for this half: `routing.preferred_failover_after_ms`
  (`internal/config/config.go:1006-1011`), wired in

## §6 — Explicit non-goal: per-request preferred-connection list (NOT this slice)

Genuinely missing, and deliberately NOT built here:

- the reference router's preferred connection is a *per-request* soft preference
  (`options.preferredConnectionIds` → `pickPreferredConnection`,
  `auth.ts:~1937`); ours is a *static role on the key*, set by the
  operator and persisted. A caller cannot say "for THIS request, prefer
  connection X".
- Verified absent in this tree: `grep -rn "preferredConnectionIds|
  PreferredConnectionIds" internal/ cmd/ web/` returns nothing (non-test
  code). There is no per-request preference input anywhere — no API-key
  preference field, no routing-contract field for it.
- This is a product decision (auth/settings surface or contract-schema
  change) and stays a named follow-up (design §S4.5 / S5, NO-GO until
  decided). Do not treat this slice as covering it.

## §7 — Deliberate divergences (design §S4.5, unchanged)

- Preferred/reserve is a static key role, not a per-request list (see §6).
- Reserve-last runs even under an explicit contract order (the contract
  names providers, never keys, so it cannot have ordered a reserve key
  first on purpose).
- Failover rotates to one sibling, pre-commit only, breaker-neutral;
  20 s default matches the reference router exactly.
